I spent six months treating my job search like a system I didn't understand, throwing applications at it and hoping something would stick. It wasn't until I sat down and actually instrumented the process — like I would any other system I was debugging — that things started to move.

## The turning point

The moment it clicked was realizing I had no logs. I didn't know which stage of the funnel was actually broken: was it the resume not getting opens, the screen not converting to onsite, or the onsite not converting to offer? I was optimizing blind.

So I built a simple tracking sheet and started treating every application like a **test case** — inputs, expected outcome, actual outcome. Some patterns showed up almost immediately. You can read more about how I think about systems like this over on my [Lenses project page](/lenses).

## What actually changed

Three things moved the needle more than anything else:

- Tightening the resume to match the actual job description, not a generic version
- Following up with a specific, non-generic message instead of silence
- Treating rejections as failed test cases worth debugging, not personal verdicts

![A screenshot of a simple spreadsheet used to track job applications](/articles/debugging-my-job-search/hero.webp)

None of this was revolutionary. It just required admitting I was flying without instrumentation, and fixing that first.
